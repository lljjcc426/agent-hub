# 事件自动化工作区复核（2026-11-15）

## 确认的问题与改造

旧页面使用独立顶部导航、绿色主按钮、灰底卡片和四个统计块，与 Chat 的统一工作区脱离。新建流程一次性展开全部接入参数和 JSON，默认授权选择器仅显示入口 ID 和时间。

现已并入 `/configure#automations`，复用现有侧栏、页头、黑白主题和语言切换。首页只有列表、搜索、状态筛选和新建入口；没有宣传副标题、空统计卡片或常驻解释小字。详情分为任务、事件记录、接入设置。维护、密钥轮换、技术记录和撤销授权按需展开。

新建分为任务和事件接入两步。默认将任务交给一个所属 Worker，自动生成基本任务结构；高级 JSON 和保存技能的固定版本保留。创建重试复用原操作 ID 和到期时间。旧地址跳转保留技能绑定参数。事件接收服务未启用时显示真实状态及按需展开的启动配置指引，不展示无效的在线启用按钮。

授权目录只列真实人类消息；自动化生成的触发输入不再混入授权选择器。原有签名、权限、回调和任务执行规则保持不变。

## 验证结果

- Node 24 的 `npm run check`：后端、Chat 和插件视图类型检查通过；97 个测试文件通过，1478 项通过、1 项跳过。跳过项是既有套件项。
- 回归覆盖：默认单 Worker 及验收文件、固定技能合约完整保留、多节点自定义、到期状态、旧地址参数跳转、过滤自动化生成的授权候选。
- 真实浏览器操作隔离 HTTP/SQLite 实例：旧地址跳转、统一导航、两步创建、跨步骤草稿保留、停止/恢复接收及刷新持久化、无副作用预演、搜索空结果、深浅色、中英文、390px 表单和列表；Chat 草稿跨导航保留，工作区选择器可正常打开。
- 通过新页面创建自动化后，发送真实签名 HTTP 事件；重复投递被去重。任务完成独立验收，回调首次返回 503 后重试成功；页面显示“验收通过”和“已送达 · 2 次尝试”。
- 浏览器控制台没有 error/warn。设计扫描的字号提示已按邻近插件工作区核对；手机标题统一为 24px。
- 原浏览器回归脚本的路由、标签、选择器和主题断言同步更新，并通过 Python 语法检查；本次浏览器操作通过 CUA 执行，没有另行运行这些 Playwright 脚本。

以上浏览器任务使用隔离实例的确定性模型和本机回调接收器，证明页面、HTTP 事件、任务状态与回传链路；不作为真实外部平台或模型能力验收。未在日常实例中创建自动化、开启接收端口或更换密钥。
